# P-Wave Detection

Train a 1D CNN (PyTorch) to classify a 10-second, 3-channel (E/N/Z) seismic
window as **Noise** vs **Earthquake**, plus a regression head that predicts the
P-wave arrival sample index. See `README.md` for the full project overview,
pipeline, and CLI reference.

## Cursor Cloud specific instructions

This is a single Python ML project (not a monorepo). It has **no servers, no
ports, no databases, and no background services** — everything runs as CLI
scripts under `scripts/`. There are also **no configured linters or automated
tests** (the README lists unit tests / CI as a future roadmap item), so there is
no lint/test command to run.

### Environment

- Python deps are installed into a local virtualenv at `.venv`, created and
  refreshed by the startup update script (`python3 -m venv .venv` +
  `pip install -r requirements.txt`). `python3-venv` is a system package that
  must exist for venv creation; it is already provisioned in the environment.
- Always run scripts with the venv interpreter, e.g.
  `.venv/bin/python scripts/<name>.py ...` (or activate with
  `source .venv/bin/activate`). Run every script from the repo root.
- CPU-only is expected and fine; the code auto-detects CUDA
  (`torch.cuda.is_available()`) and falls back to CPU.

### Data (not committed — one-time download)

- `data/` is git-ignored and must be populated before the train/eval pipeline
  can run. Download the STEAD subsample from Zenodo (record `11094536`):
  `.venv/bin/python scripts/download_stead.py --test-only` (~800 MB test split,
  enough for the full classify pipeline). The download is idempotent (it skips
  files that already exist). This is intentionally NOT in the startup update
  script because it is a large network fetch; run it once per fresh VM if
  `data/stead_subsample/` is empty. On a persisted VM snapshot the data survives
  across sessions.
- The two pre-trained checkpoints in `models/` (`seismic_cnn1d_best.pt`,
  `seismic_cnn1d_regressor_best.pt`) ARE committed, so `evaluate.py` /
  `predict.py` work immediately once windows are prepared — no retraining needed.

### Typical end-to-end flow (classification)

```bash
.venv/bin/python scripts/download_stead.py --test-only            # once, if data/ empty
.venv/bin/python scripts/prepare_windows.py --prefer-split test   # builds data/windows/{train,val,test}
.venv/bin/python scripts/evaluate.py                              # uses committed checkpoint
.venv/bin/python scripts/predict.py --index 0                     # single-window demo
.venv/bin/python scripts/train.py --epochs 12 --batch-size 64     # optional: retrain classifier
```

`prepare_windows.py` must be run before `train.py`/`evaluate.py`/`predict.py`
(they read `data/windows/`). Plots and metrics are written to `artifacts/`.

### Gotchas

- `train.py` and `train_regression.py` OVERWRITE the committed checkpoints in
  `models/`. If you only want to test the pipeline, restore them afterward with
  `git checkout -- models/`.
- Several tracked files in `artifacts/` (PNGs, JSON, reports) are regenerated by
  `evaluate.py` / `train.py`. Restore with `git checkout -- artifacts/` to keep
  the working tree clean if you don't intend to update them.
- `download_continuous.py` (SCEDC) and `live_stream.py` (EARTHSCOPE/IRIS) reach
  out to external FDSN data centers and are optional; `live_stream.py` can run
  fully offline via `--demo-replay <mseed>`.
