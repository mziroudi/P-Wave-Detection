# "Flat-then-spike" audit: what the classifier actually learned

This note documents a reproducible audit of the Noise-vs-Earthquake classifier,
prompted by the observation that earthquake windows show a flat lead-in followed
by a sharp transient. Every number and figure below is regenerated by:

```bash
python scripts/download_stead.py --test-only
python scripts/prepare_windows.py --prefer-split test
python scripts/download_continuous.py          # for the continuous section
python scripts/diagnose_shortcut.py            # writes artifacts/analysis/*.png + findings.json
```

## TL;DR

- The pre-P segment is **genuine ambient sensor noise, not zero-padding.** The
  literal "silent lead-in artifact" hypothesis is false.
- **However, the concern is essentially correct.** Because of how windows are
  cut (P pre-aligned near sample ~900) combined with **per-window z-score
  normalization**, earthquake windows have a quiet start and a loud tail, while
  noise windows have uniform energy. The model learned that **amplitude
  envelope**, not P-wave morphology.
- A **single trivial feature** (amplitude std of the first 1.5 s) reproduces the
  CNN almost exactly on the balanced test set, and the model **fires ~1,440
  false alarms/hour on quiet real continuous noise**. The 97% balanced accuracy
  does not transfer.

## 1. Is the pre-P segment zero-padded? No.

Measured on 800 earthquake traces from `test.hdf5` (raw counts, before any
normalization):

| Quantity | Value |
|---|---|
| Fraction of traces with an all-zero pre-P segment | **0.0%** |
| Mean fraction of exact-zero samples in pre-P region | **0.1%** |
| Median pre-P std (counts) | **41.9** |
| Median pre-P \|max\| (counts) | **167.5** |
| Median post-P std (counts) | **1018.2** |
| Median post/pre std ratio | **~27×** |

For reference, standalone noise traces (`test_noise.hdf5`) have a median std of
**~50 counts** — i.e. the pre-P segment is real ambient noise of comparable
magnitude to the dedicated noise traces. See `artifacts/analysis/windowing_diagnostic.png`
(top-right zoom shows clear pre-P wiggles, not a flat line).

## 2. Why it still *looks* flat, and why that's the real problem

`src/windows.py::_normalize` applies a per-window z-score. The window std is
dominated by the ~27× larger post-P coda, so the genuine pre-P noise is divided
down to near-zero and renders flat. After normalization, per class:

| Region (normalized) | Noise windows | Earthquake windows |
|---|---|---|
| std of first 1.5 s | 0.99 | **0.23** |
| std of last 6.5 s | 0.99 | 1.11 |

Noise = uniform energy throughout; earthquake = quiet start, loud tail. That is a
trivially separable envelope, independent of any P-wave physics. The root causes
are (a) the subsample pre-aligns P near a fixed index, (b) earthquake windows are
cut starting ~2 s before P, and (c) per-window normalization exaggerates the
resulting amplitude step.

## 3. A trivial amplitude baseline ≈ the CNN (balanced test set)

| Model | Accuracy | ROC-AUC |
|---|---|---|
| Threshold on `early_std` alone (`early_std < 0.59 ⇒ eq`) | **95.4%** | — |
| `late/early` energy ratio alone | — | **0.988** |
| Logistic regression on 5 envelope features | **95.3%** | **0.991** |
| **SeismicCNN1D** | **97.4%** | **0.994** |

The CNN buys only ~2 points of accuracy over a hand-coded amplitude-envelope
detector. See `artifacts/analysis/shortcut_baseline.png`.

## 4. Real continuous data: the metric that matters

Sliding-window inference (hop = 1 s, threshold 0.85) over the 1-hour Ridgecrest
recording at `CI.CLC`. The catalog origin is at t = 600 s, so the first ~9.8 min
is **quiet ambient noise with no earthquake present**:

| Quantity (quiet pre-event window) | Value |
|---|---|
| Mean P(earthquake) on quiet noise | **0.54** |
| Fraction of quiet windows with P(eq) > 0.5 | **55%** |
| False alarms/hour at p ≥ 0.85 | **~1,440** |
| False alarms/hour at p ≥ 0.95 | **~903** |

The "first alert" fires at t ≈ 20 s — ~10 minutes **before** the earthquake
exists. See `artifacts/analysis/continuous_false_alarms.png`. This is the
predicted failure mode: with no artificial quiet lead-in, the model cannot tell
real ambient noise from a real onset.

## 5. Failure cases (not cherry-picked successes)

On the balanced test set the model makes 18 false alarms and 14 misses. Their
morphology confirms the mechanism (`artifacts/analysis/failure_cases.png`):

- **False alarms** are noise windows that happen to have a quiet start followed
  by a late burst.
- **Misses** are earthquake windows whose energy is roughly uniform (no quiet
  lead-in) — one is predicted `p(eq)=0.00`.

## 6. Train/test leakage (window-level split)

`scripts/prepare_windows.py` splits at the **window level** with no grouping by
event/station/trace. Measured overlap between train and test windows:

| Overlap | Fraction of test windows |
|---|---|
| Same seismic event (timestamp) as a train window | **24.9%** |
| Same station as a train window | **94.1%** |
| Exact same trace as a train window | **1.3%** |

~25% event-level leakage further inflates the reported balanced metrics.

## Recommendations (priority order)

1. **Break the envelope shortcut.** Add negatives with the same amplitude
   envelope as positives (the codebase already has
   `extract_pre_p_noise_window`, but positives still carry the tell); apply
   consistent/global normalization rather than per-window z-score; add amplitude
   and gain augmentation so absolute/relative energy is uninformative.
2. **Report continuous metrics** (false alarms per 24 h of quiet noise, PR-AUC,
   detection latency on Ridgecrest) in the README **instead of / alongside** the
   balanced accuracy table.
3. **Show failure cases** in the README, not only successes.
4. **Grouped splitting** by event and station; add an **STA/LTA baseline** and an
   **inference-latency** benchmark (all still open).
